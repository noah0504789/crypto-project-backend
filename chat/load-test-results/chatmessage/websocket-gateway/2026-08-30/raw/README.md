# 원본 로그 (2026-08-30)

k6 표준 출력(`*.txt`)과 실행 메타(`*.meta`)다. 색상 이스케이프는 제거했다.

`*.meta` 에는 실행 시각, 대상 컨테이너 이름, **회차 중 swapin 증가량**이 들어 있다.
지연 수치를 읽을 때 swapin 을 같이 봐야 한다 — 회차 간 지연 차이의 상당 부분이 이 값으로 설명된다.

## 파일 이름

```
<라벨>-vu<VU수>-msg<메시지수>-<날짜>-<시각>.txt
```

## 회차 목록

시각은 KST. 조건은 대상 컨테이너(`*.meta` 의 `gateway=`/`chat=`)로 구분된다.

`run-wait20` 은 접속 대기(`WAIT_CONNECTED_MS`)를 15초에서 20초로 늘린 회차다.
서버 설정이 아니라 k6 클라이언트의 대기 시간이며, 접속 실패가 "느린 것"인지
"도달하지 않는 것"인지 가르려고 잰 것이다. 결과는 후자였다.

## JFR

최종 회차의 JFR 은 없다. `run.sh` 가 라벨이 정확히 `run` 일 때만 JFR 을 뜨는데
최종 회차의 라벨이 `run-final` 계열이었다. 남아 있던 JFR 은 호스트 초기화 이전
회차의 것이라 대표성이 없어 싣지 않았다.

## 읽을 때 주의

k6 요약의 `missing_total_count` 는 분모를 VU **설정값**으로 잡는다. 접속하지 못한 VU 몫까지
유실로 세므로, 실제 유실은 `broadcast(실참여 기준)` 줄을 본다.
