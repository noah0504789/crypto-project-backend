# Instructions Map

> 지시 파일의 책임과 탐색 순서만 정의한다. 개별 rule·skill·agent 목록은 [`CLAUDE.md`](../../CLAUDE.md)가 정본이다.

## 책임 경계

| 위치 | 책임 | 두지 않는 내용 |
|---|---|---|
| `CLAUDE.md` | 프로젝트 진입점, 공통 작업·완료 절차, 지시 파일 목록 | 모듈 구현 세부, 상세 규칙 본문 |
| `.claude/rules/` | 작업 유형별 행동·금지·승인 기준 | 장문 배경, 반복 실행 절차 |
| `<module>/CLAUDE.md` | 모듈 책임·고유 제약·검증 진입점 | 공통 규칙, 다른 모듈의 세부 사항 |
| `.claude/skills/` | 반복 가능한 조사·검증·초안 작성 절차 | 규칙의 정본, 모듈별 지식 |
| `.claude/agents/` | 분리된 컨텍스트에서 수행할 읽기·감사·검증 역할 | 코드 수정, 승인 판단 |
| `docs/` | 구조·흐름·설계 근거·운영 맥락 | 즉시 행동 규칙, 미확정 항목의 중복 기록 |

`CLAUDE.md`가 경로를 안내하고, rules와 모듈 CLAUDE가 행동을 제한하며, skills/agents가 절차를 수행하고, docs가 판단 근거를 제공한다.

## 탐색 순서

1. 루트 `CLAUDE.md`와 Git 상태를 확인한다.
2. 작업 유형에 해당하는 rule을 읽는다.
3. 대상 모듈의 `CLAUDE.md`와 `docs/modules/<NAME>.md`를 읽는다.
4. [`docs/README.md`](../README.md)에서 필요한 구조·흐름·테스트·운영 문서로 이동한다.
5. 반복 절차는 skill, 독립 조사·검증은 agent를 사용한다.
6. 변경 후 [`FEEDBACK_LOOP.md`](FEEDBACK_LOOP.md)에 따라 좁은 검증부터 실행한다.

## 충돌·변경 원칙

- 지시끼리 충돌하면 더 상위의 지시를 따르고 충돌을 보고한다. 문서와 코드가 다르면 코드를 사실 기준으로 삼는다.
- 기존 규칙을 다른 rule·skill·agent·모듈 CLAUDE에 복제하지 않고 링크와 해당 위치의 고유 절차만 둔다.
- 지시 파일을 추가·삭제하거나 책임을 옮기면 `CLAUDE.md`의 목록과 이 문서의 책임 경계를 함께 확인한다.
