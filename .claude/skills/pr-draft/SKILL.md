# PR 초안 작성

현재 브랜치의 변경사항을 분석해서 PR 제목과 본문 초안을 작성한다.

## 절차

1. `git diff main...HEAD` 로 main 브랜치 대비 전체 변경사항 확인
2. `git log main..HEAD --oneline` 으로 이 브랜치의 커밋 히스토리 확인
3. 위 내용을 바탕으로 아래 형식의 PR 본문 작성

## 출력 형식

`.claude/pr-draft.md` 파일로 저장한다. **1번째 줄은 반드시 PR 제목만** 담고, 3번째 줄부터 본문을 작성한다.

> 중요: 1번째 줄(제목)은 나중에 squash merge 커밋 메시지로 그대로 쓰인다.
> 본문(3번째 줄 이후)은 PR 화면에서 리뷰용으로만 쓰이고 커밋 메시지에는 들어가지 않는다.
> 따라서 제목은 "이 변경사항이 뭔지" 한 줄로 명확하게, 커밋 메시지로도 손색없게 작성한다.

```
<PR 제목 — 이게 곧 커밋 메시지가 됨>

## 변경 이유
- 왜 이 작업을 했는지

## 주요 변경사항
- 무엇을 바꿨는지 (파일/모듈 단위로 정리)

## 테스트
- 어떻게 검증했는지 (수동 테스트, CI 등)

## 참고사항
- 리뷰어(=미래의 나)가 알아야 할 특이사항, 트레이드오프
```

## 제약사항

- 이 스킬은 **파일 작성까지만** 한다. `git push`, `gh pr create` 등은 절대 실행하지 않는다.
- 파일 작성 후, 사용자에게 아래 두 가지를 함께 보여주고 승인을 받는다:
    1. **제목** (커밋 메시지가 될 부분) — 이대로 괜찮은지
    2. **본문** (PR 리뷰용) — 이대로 괜찮은지
- 사용자가 승인하면 "이제 push해달라고 말해달라"고 안내하고 끝낸다.
- 이미 `.claude/pr-draft.md`가 존재하면, 덮어쓰기 전에 사용자에게 확인한다.
